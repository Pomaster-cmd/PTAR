FIELD DEFECT
------------
The preceding INQUISITORFIX1 hardware run validates the combined native presenter:
- separate native-output presenter 1920x1080 created;
- game render swapchain remains independent;
- native presenter owns the physical Present path.

The remaining observed defect is mouse hit-test displacement. The runtime reports
that the game HWND/client envelope is native-sized while the engine raster can remain
smaller and the presenter uses its own ASPECT FIT rectangle. The historic P1U input
contract intentionally performed no mouse/raw-input remapping. That assumption is not
compatible with Inquisitor's client-coordinate UI path.

INPUTMAP1 PATCH
---------------
INPUTMAP1 changes only the final unconsumed game-WndProc forwarding path.
It remaps lParam client coordinates for these Win32 messages:
- WM_MOUSEMOVE (0x0200)
- WM_LBUTTONDOWN/UP/DBLCLK (0x0201..0x0203)
- WM_RBUTTONDOWN/UP/DBLCLK (0x0204..0x0206)
- WM_MBUTTONDOWN/UP/DBLCLK (0x0207..0x0209)
- WM_XBUTTONDOWN/UP/DBLCLK (0x020B..0x020D)

It deliberately does NOT remap WM_MOUSEWHEEL (0x020A) or WM_MOUSEHWHEEL (0x020E),
because those lParam coordinates are screen coordinates. Raw Input is untouched.
Hotkey-consumed messages are still handled before this patch and are unchanged.
GAME DIRECT (F10) bypasses INPUTMAP1 and remains pass-through.

The transform uses runtime geometry, not hard-coded game dimensions:
  sourceW/sourceH = actual REAL game-controlled backbuffer
  fitW/fitH       = current presenter ASPECT FIT image rectangle
  offX/offY       = current presenter ASPECT FIT offsets

For each client coordinate (x,y):
  mappedX = clamp(x-offX, 0, fitW-1) * sourceW / fitW
  mappedY = clamp(y-offY, 0, fitH-1) * sourceH / fitH

Invalid/zero geometry fails open and forwards the original lParam.

BINARY IMPLEMENTATION
---------------------
No C source is present in the supplied FLAT production package. This is therefore a
bounded binary patch against the exact validated INQUISITORFIX1 runtime, not a rebuild
from an approximate historical source tree.

Original WndProc forwarding site:
  VA 0x18000DF14

Patch:
  replace the original 10-byte MOV originalProc + TEST sequence with a CALL to a
  leaf remapper, commit returned EAX to R14D, then reuse the original JE and original
  forwarding blocks. The remapper reloads originalProc and sets flags before RET, so
  the pre-existing null-WndProc branch semantics are preserved.

Leaf remapper location:
  VA 0x180031517
  size 193 bytes

The remapper occupies only the pre-existing 0xCC raw padding at the end of .text.
.text raw size and file size are unchanged. .text VirtualSize is extended from
0x30517 to 0x305D8, still below the next section RVA 0x32000.

Using CALL rather than an inter-function JMP leaves a valid return address on the
stack while executing the new leaf code. The remapper performs no calls and no stack
allocation.

-------------

mouse interaction with FG still OFF. If Inquisitor uses a polling/Raw Input path for a

will identify the remaining scope without risking global input hooks.
