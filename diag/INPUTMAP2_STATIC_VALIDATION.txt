ROOT CAUSE FOUND IN INPUTMAP1
-----------------------------
INPUTMAP1 inserted a leaf remapper into the final game-WndProc forwarding path.
For remapped mouse messages, lParam is a packed 32-bit pair of client coordinates.
However the same forwarding path is also used by unrelated Win32 messages whose
64-bit LPARAM may contain a pointer or other 64-bit payload.

INPUTMAP1 entered the leaf with:
  mov eax, r14d
and committed the result with:
  mov r14d, eax

On x64, every write to a 32-bit register zero-extends the destination register.
Therefore all NON-MOUSE messages traversing that path had the upper 32 bits of
LPARAM destroyed. A pointer-valued LPARAM could consequently become invalid before
being forwarded to the original game WndProc. This is a deterministic crash-class
regression and matches the field report of systematic game crashes.

INPUTMAP2 CORRECTION
--------------------
INPUTMAP2 changes exactly two instruction encodings relative to rejected INPUTMAP1:

Leaf entry:
  INPUTMAP1: mov eax, r14d     ; truncates original LPARAM to 32 bits
  INPUTMAP2: mov rax, r14      ; preserves the complete 64-bit LPARAM

Caller commit:
  INPUTMAP1: mov r14d, eax     ; zero-extends / truncates pointer-valued LPARAM
  INPUTMAP2: mov r14, rax      ; preserves the complete 64-bit return value

The mouse-coordinate arithmetic remains intentionally 32-bit only after a supported
client-coordinate mouse message has been identified. For all other messages, RAX is
left equal to the original full R14 LPARAM and is forwarded bit-identically.

No other runtime instruction is changed relative to INPUTMAP1 except the PE checksum.
The prior INQUISITORFIX1 presenter patch therefore remains intact.

UPGRADE SAFETY
--------------
The rejected INPUTMAP1 runtime is retained as diag/r/r056.dll solely so a machine on
RC3 can be upgraded non-destructively by the existing known-proxy mechanism. It is NOT
the deployed runtime and is explicitly marked rejected in diag/r/INDEX.txt.
The stable RC2 runtime remains retained as r055.dll.

-------------

considered field-valid. FG must remain OFF for this isolation test.
