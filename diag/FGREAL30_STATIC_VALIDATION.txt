PURPOSE
-------
Historical PTAR/NVENC FG test protocols require a source near 30 FPS on a 60 Hz
output to obtain roughly 30 REAL + 30 GENERATED = 60 displayed frames. Inquisitor
does not expose a 30 FPS limiter. RC5 adds the missing source governor internally.

SCOPE
-----
Only two existing call sites are redirected:
- HookPresent active-FG FGSubmitFrame call at RVA 0x0000C798
- HookPresent1 active-FG FGSubmitFrame call at RVA 0x0000D678

Both call sites are already behind the runtime FG readiness/enable gates. Therefore
FG OFF never enters the new governor and follows the RC4 instruction path unchanged.
The governor tail-jumps to the exact original FGSubmitFrame at RVA 0x000127C0.

GOVERNOR CONTRACT
-----------------
- REAL target = FrameGenerationTargetFPS / 2.
- FrameGenerationTargetFPS=60 => REAL target ~30 FPS.
- First REAL after initialization is submitted immediately.
- QPC phase is retained for on-time frames.
- Late REAL frames are submitted immediately and phase is rebased; no catch-up burst.
- Source already slower than the cap is not additionally delayed.
- QPC/QPF failure resets governor state and fails open to the original FGSubmitFrame.
- Coarse/fine wait mirrors the existing QPC cadence concept: Sleep(1) above ~2.5 ms,
  Sleep(0) in the final phase.

PE IMPLEMENTATION
-----------------
New RX section: .fgov RVA 0x034FB000
- wrapper code size: 0x18A bytes
- unwind info RVA: 0x034FB18C

New RW section: .fgdat RVA 0x034FC000
- next QPC tick: +0x00 (qword)
- interval ticks: +0x08 (qword)
- Sleep(1) threshold ticks: +0x10 (qword)
- last target FPS: +0x18 (dword)
- armed: +0x1C (dword)

The x64 exception directory receives one sorted RUNTIME_FUNCTION entry for the new
wrapper. .pdata grows from 0x11F4 to 0x1200 using its existing 12-byte raw slack.
No absolute image-base pointer is added; all new runtime references are RIP-relative,
so the existing ASLR/DYNAMIC_BASE contract is preserved without new base relocations.

INTENTIONAL CONTRACT CHANGE
---------------------------
Unlike the historical source path, active FG now intentionally may wait in the game
Present/Present1 hook in order to impose the missing half-rate REAL cadence. This wait
exists only after the existing active-FG gate and is the sole behavioral objective of
RC5. It must not be described as preserving the old nonblocking source-Present policy.

HARDWARE GATE
-------------
Required on Inquisitor at 1280x720 / 60 Hz:
1. FG OFF remains at the already observed ~60 FPS.
2. CTRL+F6 ON converges toward ~30 source REAL FPS.
3. REAL + GENERATED output approaches ~60 displayed FPS with no crash/TDR.
4. CTRL+F6 OFF removes the cap and returns source toward ~60 FPS.
5. Mouse remains aligned and the RC4 spatial result remains unchanged.
6. Recorder remains OFF for this first isolation test.
