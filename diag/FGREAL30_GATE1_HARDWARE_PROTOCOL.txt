PTAR INQUISITORFIX1 RC7 — FGREAL30 GATE1 HARDWARE PROTOCOL

Purpose
-------
Validate one thing before further FG transport work: PTAR must NEVER cap the game to the
FG REAL cadence unless frame generation is actually enabled and its scheduler is running.

Current known separate issue
----------------------------
SHAREDIAG1 currently reports 0xF101 on Inquisitor at both 1920x1080 and 1280x720. FG is
therefore expected to fail initialization in this test. That is useful here: RC7 must still
return immediately to normal uncapped gameplay after that failed activation.

Procedure
---------
1. Close the game.
2. Install RC7 with 01-INSTALL_FULLSTACK1.bat.
3. Run VERIFY_FULLSTACK1_INSTALL.bat; PASS is required.
4. Launch Inquisitor at 1280x720 with its current VSync setting unchanged.
5. Do NOT press CTRL+F6 for 15-20 seconds. Confirm the normal FG-OFF framerate (previously
   about 60 FPS in this configuration).
6. Press CTRL+F6 once and release both keys fully.
7. Wait 3-5 seconds. FG may still fail with current SHAREDIAG1 status 0xF101.
8. Confirm that the game is NOT left at 30 FPS. It must return/remain at the same FG-OFF
   framerate behavior as before the activation attempt.
9. Press F8 once.
10. Quit normally and run diag\05-COLLECT_RESULTS.bat.

Required RC7 result while FG init still fails
----------------------------------------------
- P1FG7N ENABLED NO
- P1FG7N SCHEDULER RUNNING NO
- P1FG7N LAST STATUS 61697 / 0xF101 (until transport is fixed)
- no persistent 30 FPS governor outside active FG
- PTAR spatial presenter and INPUTMAP2 unchanged

VSync contract
--------------
RC7 does not add Auto-VSync. When Auto-VSync is implemented later, it must follow the same
strict gate: no PTAR VSync enforcement while FG is OFF or after a failed FG initialization.
