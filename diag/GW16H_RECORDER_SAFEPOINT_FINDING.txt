Static root cause
-----------------
The runtime has four late native-USR presenter branches around RVAs 0xC810, 0xC90E, 0xD6F0 and 0xD7EE.
Each called the same native post-present helper at RVA 0x14930 immediately before the existing deferred F9
capture check. SAFEPOINT1 did not wrap these calls.

The D3D11CreateDeviceAndSwapChain wrapper stores the native tuple directly:
  swapchain -> RVA 0x02C7E010
  device    -> RVA 0x0004B118
  context   -> RVA 0x02C7DFA8

This is not inferred from a name: the stores are made from the actual CreateDeviceAndSwapChain arguments.
The IID at RVA 0x00032058 is the canonical IID_ID3D11Texture2D GUID.
