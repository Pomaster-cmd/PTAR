VISUAL FAILURE
--------------
The MP4 is structurally valid, but visual output becomes severely red/black/magenta.
The first decoded video frame is visually normal. By t=0.016 s (the next 60-Hz frame),
the image is already corrupted. Therefore the corruption begins immediately after the
first native-USR recorder GPU-conversion submit, not at MP4 finalization.

F9 screenshots win81_nis_capture_1.bmp and _2.bmp were captured while recording and
show the same corruption. win81_nis_capture_3.bmp and _4.bmp were captured after the
recorder STOP and remain corrupted. This proves the corruption persists in the live
native D3D11 rendering context after recording stops.

ROOT CAUSE
----------
B18K18 conversion runs on the native game's ID3D11DeviceContext in FG-OFF/USR mode.
Its conversion helper changes live pipeline state and does not restore it. It changes:
- PS shader resource slot 0
- PS shader
- VS shader
- PS constant buffer slot 0
- IA input layout
- GS shader
- IA primitive topology
- OM render targets + depth/stencil
- OM blend state/factor/sample mask
- RS rasterizer state
- RS viewports
- RS scissor rectangles

SAFEPOINT3 correctly fixed cross-device recorder VS/RS ownership, which is why video
frames now reach QSV, but exposing the conversion on the game's immediate context made
this pre-existing state-restoration assumption unsafe.

SAFEPOINT4 / STATEGUARD1
------------------------
Only the native-USR recorder submit call is wrapped:
1. snapshot every pipeline state category modified by B18K18 conversion;
2. call the original B18K18 recorder submit unchanged;
3. restore the exact native context state;
4. Release every COM interface AddRef'd by D3D11 Get* methods;
5. return the original submit result.

Snapshot bounds:
- 8 render targets + depth/stencil
- up to D3D11_VIEWPORT_AND_SCISSORRECT_OBJECT_COUNT_PER_PIPELINE (16) viewports
- up to 16 scissor rectangles
- 17 getter-acquired COM interface references released

FG-ON isolated-presenter submit is intentionally unchanged. No ClearState, deferred
context, encoder/color-conversion change, pacing change, or hotkey change is introduced.
